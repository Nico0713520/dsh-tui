## 2. Locked Product Semantics

| Area | Required behavior | Forbidden shortcut |
|---|---|---|
| Startup | `dsh-tui` starts the interactive ACP client; `dsh-tui --echo` works without an API key | Requiring a local DSH source checkout |
| Help/version | Print and exit without spawning a backend or creating persistence files | Starting the TUI and then printing help |
| Prompting | Exactly one prompt may be in flight | Sending duplicate prompts and repairing state afterward |
| Backend failure | Mark outcome unknown and require a manual next action | Restarting and replaying `lastPrompt` |
| Cancellation | Escape sends `session/cancel` as a JSON-RPC notification with no request id | Calling cancellation as a request and waiting for its response |
| Fresh session | Create a real ACP session and reset transcript, usage, cost, watcher, partial output, and approval state | Clearing only the visible transcript |
| History | `Ctrl+R` opens “History”; replay is visibly bounded and read-only | Changing `activeSessionId` to a historical id |
| Approval | Return only an exact offered option id, or `{ outcome: "cancelled" }` | Fabricating `allow-once`, choosing the first option, or auto-allowing routine work |
| Tool logs | Incrementally read raw JSONL, retain partial UTF-8/JSON lines, and correlate call/result by id | Rereading the full file every 250 ms |
| Usage | Treat `inputTokens`, `cacheReadTokens`, and `outputTokens` as disjoint counters | Subtracting cache reads from input |
| Unknown price | Display unavailable/unknown, represented as `null` | Showing `$0.0000` as if the model were free |
| Terminal output | Strip CSI, OSC, C0/C1 controls from every untrusted boundary | Rendering backend stderr or tool arguments directly |
| Exit | Restore terminal, await backend shutdown escalation, and set a non-zero exit code on fatal failure | Calling `process.exit()` while cleanup is pending |

The user-facing v0.1 interaction remains deliberately small:

- Markdown conversation transcript.
- One-line tool call/result cards.
- Approval and History overlays.
- Enter to submit.
- Escape closes the top overlay first, otherwise cancels active work, otherwise leaves editor text unchanged.
- `Ctrl+R` opens History; a separate “New session” action inside it creates the real fresh session.
- Double `Ctrl+C` exits through awaited cleanup.
- Status shows mode/model, state, disjoint token totals, cost when known, and current session identity.

## 3. Locked Module Boundaries

```text
bin/dsh-tui.js
  -> dist/main.js
       -> src/main.ts
            -> src/cli.ts
                 -> src/config.ts
                 -> src/app.ts
                      -> src/controller.ts
                      -> src/backend/acp-client.ts
                      -> src/backend/session-log.ts
                      -> src/ui/app-view.ts
                      -> src/ui/modal-list.ts
                      -> src/ui/theme.ts
                      -> src/policy.ts
                      -> src/usage.ts
                      -> src/text.ts
            -> src/text.ts (fatal-boundary sanitization only)
```

| Module | Owns | Must not own |
|---|---|---|
| `src/main.ts` | Top-level call to `runCli()`, final sanitized fatal message, `process.exitCode`; it may also import `src/text.ts` for that boundary | TUI layout, ACP frames, config defaults |
| `src/cli.ts` | Help/version/action dispatch and calling `runApp()` | Child-process details or pi-tui components |
| `src/config.ts` | CLI/env/default precedence, validation, platform paths, JSON command arrays | Process spawning or screen output |
| `src/app.ts` | Dependency composition, terminal lifecycle, signal/error-handler installation/removal | Domain policy or JSONL parsing |
| `src/controller.ts` | State transitions and user intents | pi-tui rendering, raw JSON-RPC, direct filesystem access |
| `src/backend/acp-client.ts` | NDJSON framing, request map/timeouts, child/session/prompt/cancel/permission/close | TUI components, history parsing, auto-retry |
| `src/backend/session-log.ts` | Project key/path, incremental reads, event parsing, read-only history | ACP writes, active-session changes, UI |
| `src/ui/*` | Components, focus, rendering, user-intent callbacks | Spawning, filesystem reads, permission policy decisions |
| `src/policy.ts` | Pure risk/stakes classification | UI colors or permission replies |
| `src/usage.ts` | Pure aggregation and deterministic pricing | Mutable session state or rendering |
| `src/text.ts` | Terminal sanitization and visible-width summaries | Business state or ANSI color policy |

Dependency direction is one-way. Backend and pure modules never import UI. Controller stays renderer-independent. UI receives state and emits intents; it does not mutate backend/session state directly.

export type PermissionDecision =
  | { outcome: "selected"; optionId: string }
  | { outcome: "cancelled" }

export interface AcpClientEvents {
  onAssistantText(text: string): void
  onSessionChanged(sessionId: string): void
  onDiagnostic(message: string): void
  onPermission(request: {
    toolCallId: string
    optionIds: readonly string[]
  }): Promise<PermissionDecision>
  onBackendExit(info: {
    code: number | null
    signal: NodeJS.Signals | null
    outcomeUnknown: boolean
  }): void

export class AcpClient {

  cancel(): void

  get isPromptInFlight(): boolean
}

export type SessionLogEvent =
  | { kind: "tool-call"; callId: string; name: string; arguments: string }
  | { kind: "tool-result"; callId: string; name: string; text: string; isError: boolean }

    cwd: string

export type AppPhase = "starting" | "ready" | "working" | "cancelling" | "failed" | "closing"

export async function runApp(config: AppConfig): Promise<number>

## 5. Implementation Method

- Use test-first work inside each batch: add a failing regression, observe the expected failure, implement the smallest fix, then run the batch suite.
- Do not weaken, skip, delete, or mark a test as flaky to make checks green.
- Do not use `as any` at ACP, JSONL, config, or UI-selection boundaries. Parse `unknown` with type guards.
- Do not leave empty `catch {}` blocks for security, lifecycle, persistence, or user-visible errors. Convert expected absence to a typed result; surface malformed/unexpected input as bounded diagnostics.
- Child stderr uses a pipe, not inherited terminal output. Sanitize and bound it before sending one diagnostic event to the controller.
- All timers, listeners, file handles, readline instances, and child processes need an owner and an idempotent cleanup path.
- Old files are deleted only after replacement tests pass and `rg` shows no remaining imports.
- Do not amend or squash the six implementation commits. GPT-5.6 needs the batch history for review.
- If one test fails, keep repairing within the same batch. Do not move the failure into a later batch.
