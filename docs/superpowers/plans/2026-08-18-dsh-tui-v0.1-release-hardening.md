# dsh-tui v0.1 Release Hardening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把当前 `2d7a4a3` 本地候选版完善为可公开发布的 dsh-tui v0.1：默认连接真实 ACP、跨平台组合正确、历史和生命周期可靠、窄屏视觉可用，并具备 GitHub/npm/抖音所需的发布素材。

**Architecture:** 保留 `config -> app composition root -> controller -> backend/log ports -> pi-tui view` 的现有结构，不引入第二套状态机或 UI 框架。正确性修复继续落在各自所有者模块；真实终端行为由 PTY 测试覆盖；发布素材从经过脱敏的真实 TUI 流程生成，不在产品代码里添加隐藏演示分支。

**Tech Stack:** Node.js `^22.19.0 || >=24.0.0`、TypeScript 6、Vitest、node-pty、`@earendil-works/pi-tui@0.84.2`、DeepSeek Harness `0.1.0-rc.7`、GitHub Actions、npm。

## Global Constraints

- 从提交 `2d7a4a3` 开始；先确认工作树没有无关修改。发现用户已有修改时保留，不覆盖、不重置。
- 连续完成 Task 1–8；每个任务测试通过后提交，但不等待用户逐批审核。最终统一交给 GPT-5.6 做代码审查。
- 不按耗时拆任务，不增加竞争分析、插件系统、主题市场、会话分支或其他 v0.1 之外功能。
- `dsh-tui` 默认启动真实 ACP；只有 `dsh-tui --echo` 或显式 `--mode echo` 才进入 Echo。
- Echo 不要求 API key；ACP key 只能从 `DEEPSEEK_API_KEY` 环境变量读取，任何文件、命令输出、测试快照、GIF 和提交都不得包含凭据。
- DeepSeek Harness 依赖统一固定为 `0.1.0-rc.7`；除直接声明已使用的 `@deepseek-ai/dsh-shell-env` 外不增加运行时依赖。
- macOS/Linux 使用 Bash 工具；Windows 只向模型暴露 PowerShell 工具。三平台均支持 Node `22.19.x` 和 `24.x`。
- 所有后端、日志、工具名、工具参数、异常和历史文本在进入终端前必须移除 CSI、OSC、C0/C1 控制字符。
- 不自动重试或重放结果未知的 prompt；新会话必须创建真实 ACP session 并重置 transcript、usage、cost、watcher、partial output 和 overlay。
- Task 1–8 只生成本地 release candidate。不得 push、tag、创建 GitHub Release、公开仓库、npm publish 或修改仓库公开状态。
- 每个任务遵循：先写失败测试、确认失败、做最小实现、跑目标测试、跑相关回归、提交。不要用跳过测试代替修复。

- [ ] **Step 4: Centralize child finalization**

Implement one child-finalization path with this shape:

```ts
private finalizeProcess(
  child: ChildProcessWithoutNullStreams,
  error: Error,
  code: number | null,
  signal: NodeJS.Signals | null,
): void {
  if (this.process !== child) return
  this.process = null
  this.output?.close()
  this.output = null
  this.initialized = false
  this.sessionId = null
  this.promptInFlight = false
  const outcomeUnknown = this.pending.size > 0
  this.rejectPending(error)
  if (!this.closing && !this.closed && !this.exitReported) {
    this.exitReported = true
    this.events.onBackendExit({ code, signal, outcomeUnknown })
  }
}
```

The `error` listener must call it with a sanitized spawn error. The `exit` listener must call it with the existing outcome-unknown error. Only the first path for a child may mutate state or report exit.
