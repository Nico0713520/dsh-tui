# dsh-tui v0.1 Public Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a safe, installable DeepSeek Harness TUI that runs a real model/tool flow, can be published on GitHub/npm, and produces a reproducible Douyin demo.

**Architecture:** Keep pi-tui and the DSH ACP transport, but split configuration, ACP lifecycle, JSONL observability, application state, UI, safety, usage, and terminal-text handling into focused modules. ACP owns fresh prompts/cancellation/permission requests; a raw JSONL side channel owns tool cards, usage, and read-only history. Implementation runs as six broad autonomous coding batches with automated checks instead of human review gates.

**Tech Stack:** Node.js `^22.19.0 || >=24.0.0`, TypeScript ESM, `@earendil-works/pi-tui@0.84.2`, DeepSeek Harness `0.1.0-rc.7`, Vitest, tsdown, oxlint, node-pty, GitHub Actions.

## Global Constraints

- Pin every `@deepseek-ai/*` runtime package to `0.1.0-rc.7`; upgrade only in a separate compatibility change.
- Treat ACP as fresh-session-only. v0.1 history is read-only and never claims resume/continuation.
- Use `persistenceCompression: none` for the TUI-owned persistence root because the log reader consumes JSONL directly.
- Never automatically replay a prompt after backend failure or cancellation.
- Permission uncertainty fails closed; missing/invalid choices never grant access.
- Keep `@earendil-works/pi-tui` as an external dependency; do not patch its source.
- Preserve Chinese/CJK terminal correctness and support Windows, macOS, and Linux paths without hardcoded machine locations.
- Run batches continuously. Ask the user only for unavailable credentials, publication authority, or a product decision that changes the approved design.

export function classifyShellCommand(command: string): "benign" | "destructive" {

}
